# Pull request quality checks

The Quality workflow runs for pull requests targeting develop, pushes to develop,
and manual dispatch. No production secrets, remote AI service, or real database
are required. Backend tests use disposable in-memory SQLite fixtures.

Required check names:
- Backend tests
- Frontend checks
- Patch formatting

Backend: Python 3.13, locked Pipenv dependencies, syntax/indentation checks and
unittest discovery. Frontend: Node 20, npm ci, ESLint, Node tests and Vite build.
Pip and npm download caches are keyed by their lockfiles. Jobs have read-only
repository permissions, timeouts, and cancellation of obsolete runs.

Formatting checks reject whitespace errors on added PR lines without forcing a
repository-wide rewrite. ESLint checks correctness with the recommended rules;
unused variables are temporarily exempt because the existing UI contains legacy
placeholders. Intentional infinite pagination loops are allowed. This is not a
full autoformatter enforcement policy.

Local equivalents:

```bash
pipenv verify
pipenv sync
AUTH_TEST_DATABASE_URL=sqlite:// PYTHONPATH=src:tests pipenv run python -m unittest discover -s tests -p 'test_*.py' -v
npm ci
npm run lint
npm test
npm run build
git diff --check
```

Never point AUTH_TEST_DATABASE_URL at a persistent database: tests create and drop
tables. Do not print environment variables or provide real credentials to CI.

Require the three named checks in develop branch protection, preserving existing
review requirements. A failed workflow alone does not prevent merging unless
required checks are configured. Administrators may retain bypass privileges.
